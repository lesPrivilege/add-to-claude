# Work Order 02 — 双轨 Icon Design / 参考消费与视觉交付

**产品：** gpt-handoff（macOS menu-bar/top-bar 工具）  
**输入：** 同目录 `GPT-Handoff-Design-Reference-Registry-2026-10-16.md`  
**工单类型：** 视觉设计 + 可编辑生产工件；独立于增量 Handoff 实现  
**状态：** 参考已登记，图形未裁决。请先研究、后构图，不沿用先前失败 SVG 作为默认底稿。

## 任务

建立一块**有源可溯的对照参考板**，从 Apple 原生规范、真实 Mac 菜单栏产品与优质 App Icon 图库提炼不同层次的图标 grammar。在此基础上提交 **三组有辨识度的成对 icon 设计**，每组包含原生 menu bar glyph 与独立 macOS app icon。设计应在真实大小、真实使用环境中成立。

**产品动作：** 从 ChatGPT 当前或选定会话读取内容，填入用户选择的 Claude / Codex 等本地 Agent composer；不替用户发送。Icon 只需要承载 `composer + 纳入`，而非负载数据来源、下载、发送和 AI 生成的全部隐喻。

## 已知否决与主观方向（不要忽略）

- 两条斜射线 + composer：在 App Icon 观看尺寸下读成**手提包的提手 / 收音机天线**；已否决。
- 收腰或线条融合：容易读成**烧瓶**；梯形穿框可能像**打印机输纸器**。不得把过去 H/M2 系列仅缩短一截就重新交付。
- 四尖星 Sparkle 已沦为通用 AI 语法；避免。闪电太像加速/快捷命令，并不准确表达填入。
- C 类 composer + 垂直注入更接近产品语义，但可以优化动作：**一道倾斜划过、由细到粗且带短拖尾的弧形轨迹**，在 composer 内终止，而非两条平行/对称光线。
- 前述是设计线索，不是要求先入为主地画一条弧；若参考研究得出更好方案，允许另起方向并解释。

## Step 1 · 消费来源，做一块真正有用的 Reference Board

先消费 registry 的 **N01/N02/N03/N04、C01/C02/C03/C04/C06**。不足时再查 C05 与 L01–L03。每条至少保留原始 URL、作者/官方归属、访问日期、截图出处、实际要学的 grammar、迁移/禁止迁移的部分和授权备注。参考板不要用随机渲染图或其他 AI 生成图冒充现存产品。

- **菜单栏板：** 4–6 个具体产品/系统例子；如 CleanShot X、PopClip、Bartender、系统 Symbols。分别裁剪真实 menu bar 环境并放在固定基准尺寸下，标注重量、角半径、空白与误读。
- **App Icon 板：** 6–8 个 macOS 应用图标，从 Raycast Press 和 macOSicons 目录选；记录一个主要形体如何借助底板、阴影、冷色照明与深度形成辨识度。不要只生成泛泛 Pinterest/Dribbble 氛围拼贴。
- **Skill 检索：** 可消化 Anthropic `frontend-design` 的产品特异性原则与 `canvas-design` 的视觉思想，但不要把它们作为图标路径工具，也不准为装 skill 引入大批依赖。

板的产出：一个 `references.md` 和一张可直接并排看的 reference board（本地 HTML 或 PNG 均可）。图像版权归各原权利人；附原链接与用途，不作为可发行图标资产打包。

## Step 2 · 三个「概念成对、形态分离」的候选

| 方向                                   | menu bar / menu item                                                       | app icon                                                                    |
| -------------------------------------- | -------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| D1 · Arc Insert                        | 一道短弧/划过轨迹实际进入极简 composer；灰度，近系统符号的字重与边距       | 品牌化的掠过轨迹、冷色光感及一个清晰的接收区域；不必与 glyph 使用同一条路径 |
| D2 · Cursor Arrival                    | composer + 光标为重心，入口只用少量负形表达，优先确定「正在被填入」        | 以光标出现/文本承接的一瞬作为独立视觉主图，可以用分层材质与局部光晕         |
| D3 · Negative-space Insert / alternate | 借 composer 的开口或空间关系表达接纳，少画机械件；可以跳出“从上向下”的方向 | 将空间穿入转成有质感的原创材质符号；不能退回打印机/烧瓶                     |

菜单栏与 app icon **不要求共用 SVG**、颜色、细节或者几何轮廓。只共享动作隐喻与一组可解释的视觉特征；可检验其品牌亲缘。

## Step 3 · 光学校正而非放大评美

**菜单栏：**

- 原生状态栏真实视距，和 Apple 系统图标或已有 tool glyph 混排；16/18/20pt（根据实际项目目标系统校准），@1x/@2x，明/暗外观。
- 原生单色 template image；对比线重、cap、join、曲线终点、字重/视觉重心；不得靠渐变、透明拖尾、小点、微型双线等脆弱线索表达关键意思。
- 在 16pt 原生尺寸下，先遮住旁边文字，请未参与设计的人报告第一眼联想到什么。任何高频「手提包/收音机/天线/打印机/发送」误读都要消除。

**App Icon：**

- 在 Dock/Launchpad/设置/ Finder 的真实背景显示 32/64/128/256px；检查饱和度、体积、边界、层次以及低尺寸的主体完整性。
- 可用双色或少量冷色渐变、反射、薄玻璃等，但必须克制，不做大面积空洞 AI 霓虹，也不要像系统菜单 glyph 加了彩色底板。
- 确保主视觉与背景、系统图标及真实 Mac 工具集放在一起时不突兀。尽可能保留可编辑源图及分层文件；支持 Icon Composer 时可用其原生 pipeline。

## Step 4 · 交付与裁决

必须交付：

1. **可追溯 Reference Board**（真实外部样例 + 逐项学习点）及一页提炼出的 grammar。
2. **3 × 2 对照板**：三个设计概念，每个有 menu glyph / app icon 两种产物；同时显示在系统环境内和独立白底/深底预览。
3. **矢量源与导出**：菜单栏 SVG/PDF 或项目要求的 template image（含 @1x/@2x）；App Icon 原始分层路径和适配系统的预览/资产格式。不把临时 raster 图当唯一源文件。
4. **短评审**：每方向独有优点、已发现的误读、16pt 的辨识、32px 的品牌辨识与明确的推荐顺序。用户裁决前不要擅自将一个提案合并到正式 App Icon。
5. **独立分支 / 产物索引 / 测试记录**：以实际 repo 为准（候选 `design/handoff-dual-icon`）；不改会话增量逻辑，不合入 main。

**Design quality bar：** Menu bar 首要“像原生”，App Icon 首要“精致且可记住”。如果 D1 仅放大好看、缩小就变成别的器物，应被否决，不准靠口头解释补救。先完成视觉 Output，再由独立 fresh reviewer 审看误读、授权、原生适配与一致性。
