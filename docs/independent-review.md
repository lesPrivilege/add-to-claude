## What the reviewed boundaries do well

- The bridge binds to `127.0.0.1`, verifies the exact runtime Host and Origin, rejects cross-site fetches, requires a session capability, sends no CORS permission, and serves a fixed path allowlist under a restrictive CSP.
- Target registration, staging, claim, and receipt are separate states. Identity, instance, readiness, draft revision, expiration, cancellation, and claim token checks prevent a stale selection from silently becoming a different controlled composer.
- The browser desk says `Copied` for a successful clipboard write. `Added` requires a matching controlled-composer receipt. Native source only reports verified append after exact accessibility readback; failed readback warns that the draft may already have changed.
- Imported selected paths use parent ancestry, preserve original text parts and locators, keep sibling branches separate, mark recognized unfinished/nontext content partial, and retain expired/inaccessible attachment references.
- UI previews use `textContent`; JSON and transcript content are never evaluated as code. The bridge accepts no arbitrary filesystem paths, file execution, send action, or shell command. Attachment names, types, decoded sizes, and base64 form are bounded.
- Browser transfers append by default; replacement is an explicit selection. Native append preserves the latest readable plain-text value and never emits Return or a synthetic paste shortcut.

The session capability protects the browser boundary; it is not a security boundary against arbitrary software already running as the same local user. A hostile local process can call the bootstrap endpoint directly. The native README correctly treats its health marker as compatibility checking, not authentication of other local software.

Collection merges stable message IDs through overlapping rendered windows and requires one unambiguous order. It preserves distinct IDs with identical text, rejects changed overlapping content/links/files and contradictory order, and aborts on streaming, source navigation, disconnected windows, missing IDs, cancellation or user takeover. Time, steps, turns and serialized bytes are bounded. Missing ranges and limited/stalled outcomes remain explicit. Reaching the observed start and end never upgrades DOM completeness or original-Markdown fidelity.

The page helper holds only a bounded in-memory scroll lease. Normal completion/cancellation releases it; changed-page failures may leave only the bounded lease until its timer cleans up. It does not restore another document or override trusted user takeover. The popup port locks collection before asynchronous work, reports observed counts rather than invented percentages, and aborts when disconnected. These are source and fixture observations; actual extension worker suspension and action-popup behavior still require the installed-extension acceptance run.

Download assistance requests an optional permission only when invoked. It initiates a selected exposed HTTPS file through the normal browser API, follows only the exact returned download ID, forwards no absolute path, never accepts a danger warning, and does not open or execute the file. Its receipt is completion metadata, not bytes. The desk separately accepts explicitly selected Files, rejects ambiguous or mismatching name/size associations, honors an existing expected digest, calculates the selected bytes' SHA-256, and preserves the source locator. Filename/size agreement is user-confirmed association, not independent cryptographic proof of source bytes. A completed download is never marked as an available attachment until its bytes have been selected.

Normal downloads can continue after the popup closes. Polling, cancellation and worker lifetime are not a hard network-byte cap; accepted bytes still meet the desk/bridge bounds. Page-handler-only, expired, inaccessible, unknown-name or unsupported downloads retain the normal source action. No cookies/tokens, global download history, directory handle, persistent transcript store, per-turn clipboard-reading loop or external agent runtime was added. The official [Chrome download API](https://developer.chrome.com/docs/extensions/reference/api/downloads) was checked for this review; it supplies operation metadata, not a file-byte read method or expected hash.
