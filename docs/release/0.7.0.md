# Add to Claude 0.7.0 · technical beta

_Talk it through in chat. Finish it in your agent._

## What's new since 0.6.1

- **Terminals.** The window picker lists the windows of any terminal app (Terminal, iTerm2, Ghostty, WezTerm, Warp, Kitty…) under **Terminals**. A terminal never receives the conversation itself: Add saves it as a hand-off file in the conversation's files folder, puts one line on the clipboard, `@"/path/to/handoff-….add-to-claude.md"`, and brings that terminal window forward. You press ⌘V where you want it; in an agent the line is a file mention, at a shell prompt it is an unexecuted line, and the path holds nothing a shell would act on. Then **It's There** counts it as added, or **Copy Again** puts the line back on the clipboard.
- **Hand-off files.** One per conversation and terminal window, replaced by each Add there. Clear History removes them, and each is removed once it is a day old, when the app starts or the panel opens. A file of that name that Add did not write, or that you edited, is left alone.
- **Choosing turns.** Click anywhere on a row to check or clear it, or drag across rows to give them all the same state. The popover no longer clips its edges, and neither does the files list.
- **"New since last add" says why it is unavailable.** Before a first Add to a target, or in a window that does not identify its conversation, the item is greyed out with the reason under it, instead of looking clickable and doing nothing.
- **Unreadable markup is flagged.** ChatGPT markup the reader cannot parse is kept as written, and a content check at the top of the text says so.
- **Several sources in one citation** read smallest number first: `[1, 2]`.
- **Fixed:** a file name containing `$&` or `` $` `` could bring the account id back into a check line.
- **The project is public**, under the MIT License, with contributor and security guides, a spec of the hand-off format and a threat model.

## Install

Apple silicon, macOS 14 or later.

1. Download `add-to-claude-0.7.0.zip` below and check its SHA-256: `SHA256_PENDING`.
2. Unzip and move **Add to Claude** to Applications, then open it. macOS refuses the first time: System Settings → Privacy & Security → **Open Anyway**.
3. Sign in to ChatGPT in the panel, choose **Allow…** for Accessibility, click once into the message box you want, choose its window in the bar, and **Add**. Terminals need no further permission.

## Updating from 0.6.1

Quit Add to Claude, replace **Add to Claude** in Applications with the new one, and open it. Settings, sign-in and the Accessibility grant carry over: the bundle id and signing certificate are unchanged.

What Add remembers is now stored with a format version, and the files 0.6.x wrote are dropped once, on the first launch. So the next Add into each conversation offers **All** again, and files are downloaded again once. Nothing you saved or downloaded is deleted.

## Known limits

As in [0.6.1](0.6.1.md#known-limits). For terminals:

- A target is a terminal window, not a tab: you choose the tab when you paste. Add does not read the screen or name what runs there; you see both when pasting.
- Whether the line landed is yours to say. A copied line is not a pasted one, so Add records it as added only after **It's There**.
- A terminal inside an editor, such as VS Code's, is not listed: its window is the editor's.
- Automatic delivery into a chosen tab was tried for Terminal and iTerm2 and dropped: on the owner's Mac, Terminal did not take the line while in the background. The record is in [decisions/reading-and-projection.md §4](../decisions/reading-and-projection.md#4-terminals-receive-one-line).

## Your terms

## Review and checks

Three independent Opus reviews and one cold read:

- **The maturity work** (module splits, the unreadable-markup check, versioned records, the shared bridge fixture): five findings fixed, among them the `$&` account-id leak; one kept by the owner (a malformed ready message reads "could not be read").
- **The first terminal design**, which delivered into a chosen tab over Apple Events: nine findings fixed, among them shell-active characters in the path, programs other than shells and agents, and the clipboard on an unconfirmed paste. That path was later removed after the owner's run.
- **The paste-by-hand design and the turn-picker work:** eleven findings fixed, among them a drag that slipped sideways repainting every row to the end, a composer choice that left a terminal as the target, and one hand-off file shared by two terminal windows (now one per conversation and window, the owner's call).
- **A cold read of the README, CONTRIBUTING, SECURITY and the docs index** against the project's writing guide: findings adjudicated one by one; what 0.6.1 had versus 0.7.0, the paste fallback and what reaches the disk are now stated.
