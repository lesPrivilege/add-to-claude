# Add to Claude 0.6.1 · private technical beta

_Talk it through in chat. Finish it in your agent._

## What's new since 0.6.0

- **One turn per exchange.** When ChatGPT says "I'll look at…", runs a tool and then answers, that is now one turn, in source order, instead of a separate turn for the note. Its source comment lists every message it came from, and **New · N** counts exchanges.
- **Citations stay where they were.** Each citation in an answer leaves `[n]`, the number of its source in the turn's numbered References list (sources cited in the text come first); one that could not be matched to a source leaves `[?]`, so a reviewer can check it on the spot.
- **Files are not downloaded twice.** A file Add saved is reused on the next Add, after a relaunch too, as long as it is still there with the same bytes (checked by SHA-256). This record follows Settings → History: kept for the history period, removed when Remember is off, forgotten by Clear History. The files themselves are never deleted.
- **Cards read as plain text.** A laid-out answer's boxes go flush left in reading order, so nested cards no longer leave deep indentation that reads as code; fenced code and writing blocks keep their own indentation. ChatGPT's `<MemoryCite/>` mark is dropped.
- **"Add to Claude.app".** The app's bundle now has its proper name in Finder and Launchpad.

## Install

Apple silicon, macOS 14 or later.

1. Download `add-to-claude-0.6.1.zip` below and check its SHA-256: `c6ae851c7f4c84490b90f8dd2507a82f9f8f02553f3dcf0aad9305a061b22c33`.
2. Unzip and move **Add to Claude** to Applications, then open it. macOS refuses the first time: System Settings → Privacy & Security → **Open Anyway**.
3. Sign in to ChatGPT in the panel, choose **Allow…** for Accessibility, click once into the message box you want, choose its window in the bar, and **Add**.

## Updating from 0.6.0

Quit Add to Claude, move `add-to-claude.app` from Applications to the Trash, then install **Add to Claude** as above. Settings, sign-in and the Accessibility grant carry over: the bundle id and signing certificate are unchanged.

## Known limits

As in [0.6.0](0.6.0.md#known-limits). A card's arrows and side-by-side layout are not drawn: its words come through in reading order, and the relations are left to the reader. A citation whose id the answer itself got wrong reads `[?]`, like any other that cannot be traced. A message you send while ChatGPT is still working sits where it was sent: the note before it and the answer after it stay two turns, in source order.

A reply that finishes while the panel is closed or the page is idle is read when the conversation is opened again; use the reload button at the panel's top left (⌘R) for a long-running task.

## Review and checks

Independent Opus review of the uncommitted 0.6.1 diff:

- **Fixed:** citation placeholders could rewrite text they did not belong to (private-use characters in code, in user turns). Marks now travel as a character absent from the message and come out as positions; the text is never rewritten. Regression test added.
- **Accepted:** a turn that grows by a folded message after an Add counts as changed, not new. Add is off while a reply streams, and the note, tool call and answer arrive in one stream, so this needs an interrupted reply.
- **Accepted:** the first use of a saved copy after a relaunch hashes it on the main thread, once per file per run.
- **No action:** a fallback attachment id outside any turn could in theory shift to another file; not seen in real data shapes, and the hash check still guards reuse.

Checks: `npm test` 120/120 (after the review: `<MemoryCite/>` and flush-left cards); native delivery log 120, WebKit 34; Accessibility 54 (owner's terminal, 2026-10-17, on `8a727f3`); browser suite not run on 0.6.1 (its Chromium was removed in the fresh-install cleanup); its 14/14 from 0.6.0 carries over, since the page observer and its scripts are unchanged since `v0.6.0`.

Owner's run on rc.2 and rc.3 (2026-10-17), one real conversation with web citations, a plugin search and a layout card: the pre-search note and the answer arrived as one turn; incremental New offered only the new turns three times running ("Turns 3–4 of 4", "5–6 of 6", "7–10 of 10"), verified when nothing needed a check; unmatched citations read `[?]` in place; on rc.3 the card read flush left with no code block and no `<MemoryCite/>`.
