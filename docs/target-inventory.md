# Target choices

Reviewed 2026-10-12 against the primary sources linked below. This is a bounded inventory of recognizable desktop, editor, and terminal targets. It is descriptive metadata for a small picker, not an exhaustive market census or a compatibility promise.

Every external target uses the same prepared transcript and common clipboard path. A target label may add a short focus hint; it does not install an app, start an agent, change its settings, obtain an account, or send a prompt. Keep adaptation limited to identity, selected window/composer, and trustworthy readiness checks.

## Transport groups

| Group                            | Required user selection                                     | Transfer claim permitted                                                                                                              |
| -------------------------------- | ----------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| Controlled browser test composer | Exact local harness instance and its draft field            | Verified insertion only after that instance acknowledges matching content and attachments. This establishes the harness path alone.   |
| Desktop composer                 | Running app, correct conversation/window, editable composer | Generic clipboard/manual paste unless the particular native path was tested and draft readback succeeds.                              |
| Editor chat panel                | Editor window/project and the chosen assistant's input      | Generic clipboard/manual paste. Editor identity cannot distinguish chat, source editor, search, or terminal focus.                    |
| Terminal agent                   | Existing interactive agent prompt, selected by the user     | Copy for manual paste. Never automatically paste to an ordinary terminal; process/window branding does not establish safe input mode. |
| Other composer                   | Explicitly selected destination                             | Clipboard fallback with no claim of paste or attachment support.                                                                      |

## Keep the picker thin

Implementation only needs a stable local choice ID, human label, transport group, concise focus hint, and evidence/status label. These fields must not imply executable launch commands, supported APIs, inferred window identity, or per-vendor attachment support. Labels can be updated without changing the transcript model or clipboard transport.

Do not show an unavailable/native-untested choice as “connected.” Show “Copy for …” when the only proven action is a clipboard write. After copying, say “Copied — paste into …”; after a verified harness insertion, say “Added to test composer.” If focus changes, readiness fails, or an acknowledgement is missing, offer retry/cancel and leave the result unverified. A retry must not duplicate an earlier acknowledged draft.

The readable projection starts with a neutral transcript label and explicit source/role delimiters so that a turn beginning with `/`, `!`, a shell command, or instruction-like text remains transcript data. This is useful separation, not a guarantee against downstream prompt injection. Only the user decides whether to submit the prepared draft.

## Evidence levels

- **Discovered:** official documentation identifies the product and its input surface.
- **Implemented:** a code path exists in this repository; its behavior still needs evidence.
- **VM-tested:** the named path passed synthetic tests in the cloud Linux VM. A harness test cannot confer this status on an external product.
- **Native-untested:** macOS code or intended behavior was reviewed but not run on macOS. Accessibility, focus, clipboard formats, app updates, and file insertion remain unverified.

Use these levels per path, not a single “supported agents” badge. This inventory does not turn documentation review into a test result.
