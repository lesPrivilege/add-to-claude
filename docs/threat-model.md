# Threat model

What Add to Claude trusts, what it does not, and what each boundary checks. It covers 0.6.1 and the terminal destination on `main` since. Report a problem through [SECURITY.md](../SECURITY.md).

## What is worth protecting

- **The user's ChatGPT session.** The panel's cookies and the page's session token.
- **Conversation text and files.** They must reach only the target the user chose, and only when the user presses Add.
- **The target app or terminal.** Nothing may be sent or run in it.
- **The user's disk.** Files land only in the chosen folder, and only the records described in the README are written.

## Who might act against it

- **The ChatGPT page.** The page itself, or anything injected into it, such as a compromised script or a crafted conversation. The conversation text is fully controlled by whoever wrote the messages, and an answer may quote anything.
- **Other web content.** A link opened from the conversation, or a frame inside the page.
- **Other apps on the Mac.** These can change windows, focus or the clipboard between choosing a target and Add.
- **Out of scope.** A local attacker with the user's privileges, who could read the WebKit store and the app's files anyway.

## Boundaries and their checks

| Boundary                     | Check                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Page world → isolated bridge | The observer runs in the page world, so a hostile page can shape what it reports: every packet is page-controlled. The bridge accepts packets only on the one private `MessagePort` handed over at document start; packets posted by the page, a second port and other windows are ignored. The bridge compiles and validates them in the app's own content world, which page scripts cannot see. (`src/page-observer.js`, `src/bridge.js`; `tests/bridge.test.js`)                                                                                                                          |
| Bridge → native              | A message counts only when it comes from the panel's own web view, the isolated world, the main frame and an https origin on `chatgpt.com` or `chat.openai.com`, for the page on screen. Every field is re-read natively: sizes (16 MiB of text, at most 1,000 files and 5,000 turns), line numbers inside the text, SHA-256 shapes, labels cut to length, and check codes of a fixed form. A malformed result is refused whole. (`native/Chat.swift`, `native/Prepared.swift`; WebKit suite)                                                                                                |
| Conversation text → hand-off | Text is data. The hand-off is plain Markdown. The preview shows it as text, never as trusted HTML. Comments carry locators only. Account ids are cut out of file names. (`src/projection.js`, `src/export-files.js`)                                                                                                                                                                                                                                                                                                                                                                         |
| Navigation                   | The panel stays on ChatGPT's hosts and the sign-in hosts. Any other link opens in the default browser, and popups open only for sign-in. (`native/Chat.swift`)                                                                                                                                                                                                                                                                                                                                                                                                                               |
| File links → download        | A link counts only if the page itself fetched it for that file on that conversation's page. It must be https, on ChatGPT's hosts or `*.oaiusercontent.com`, and still fresh. The download runs through the chat's own WebKit session: no cookie or token is read or copied. A stalled download is cancelled after two minutes. (`native/Chat.swift`, `native/Files.swift`)                                                                                                                                                                                                                   |
| Download → disk              | A file's name stays inside its folder: no separators, and never `.`, `..` or a hidden name. Files go in one subfolder per conversation under the chosen folder. A name already taken gets the first free `name 2`. A second copy with the same bytes is removed rather than kept twice. A saved copy is reused only while its SHA-256 still matches. (`native/Files.swift`, `native/Delivery.swift`; delivery-log suite)                                                                                                                                                                     |
| Native → target app          | Text is appended at the end of the focused text area of the window the user chose. The app is never activated, and Return is never pressed. If the app ignores the Accessibility write, the fallback pastes with ⌘V sent only to that app. Before that keystroke, it checks that the source, the target conversation, the draft and the caret are unchanged. The clipboard is restored unless something else was copied meanwhile. Success means the text was read back. Otherwise the bar says it could not confirm and asks the user. (`native/Composer.swift`; Accessibility suite)       |
| Native → terminal            | Add never types or pastes into a terminal. It puts exactly one line, `@"<path>"`, on the clipboard: an absolute path with no control character, newline, or character a shell acts on inside double quotes (`"`, `$`, backticks, `\`, `!`); folder names are cleaned of them and a files folder whose path has one is refused. Then it un-minimizes and raises the chosen terminal window and activates its app, after checking the window is still open in the same run of the app. The user pastes; whether it landed is theirs to say. (`native/Terminal.swift`; bar suite for the logic) |
| Hand-off file → disk         | One `handoff-<conversation>-<window>.add-to-claude.md` per source conversation and terminal window, so neither two conversations with one title nor one conversation in two windows share it; replaced by each Add there. The path is checked before anything is written. Only the paths Add wrote, with their times and SHA-256, are remembered; a file Add did not write, or that changed since, is never replaced or removed. Clear History removes them, and each is removed once a day old, at launch or when the panel opens. (`native/Terminal.swift`; bar suite)                     |
| Records on disk              | The delivery log and the saved-files record are written to `~/Library/Application Support/add-to-claude/`: a 0700 folder holding 0600 files. They hold ids, positions, hashes, paths and times, never message text or account ids. Diagnostics, in the unified log, hold counts and fixed names only. (`native/Delivery.swift`, `native/Diagnostics.swift`)                                                                                                                                                                                                                                  |

## Accepted risks

- **Page-shaped content.** A hostile ChatGPT page can make the hand-off say anything, as the conversation itself can. The guarantee is that it stays text, reaches only the chosen target, and is never sent. Whether to act on it is the receiver's call, which is why quoted instructions arrive as material.
- **The clipboard for a terminal.** Add replaces the clipboard with the one line and does not restore it, since the user is about to paste it.
- **The clipboard during the paste fallback.** For a moment the conversation is on the general clipboard. If the paste cannot be confirmed, it stays there so the user can paste it by hand, and the bar says so.
- **The one line at a shell prompt.** If the user pastes it at a shell prompt, the line sits unexecuted until they delete it or press Return; Return runs `@"…"` as a command, which the shell does not find; the path holds nothing the shell would substitute or expand first. The user sees what the tab runs when pasting.
- **The hand-off file is a copy of the text on disk** until it is a day old and the app starts or the panel opens, in the folder the user chose, with the user's permissions. Any process running as the user can read it, as it can the downloaded files.
- **Accessibility is a broad permission.** macOS grants it to the whole app. The app uses it only to find text areas, read them, and write to the one the user chose.
- **Signing.** Releases are signed with the author's own certificate. They are not notarized and have no hardened runtime. Users get the app from the GitHub release and check its SHA-256.
- **Terms.** The app reads ChatGPT's page data and asks for file links through the user's own session. Whether that fits the terms that apply is the user's to check.
